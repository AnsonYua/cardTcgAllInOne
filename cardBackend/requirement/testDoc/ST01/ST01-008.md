
  1. Blocker choice redirects an attack and rests the blocker

  - Setup: Player A has a unit in slot1 to attack with. Player B has ST01-008 in slot1 (active) and another unit
    in slot2 to be the original target. currentPlayer = A, phase = MAIN_PHASE.
  - Action: Load `ST01-008/blocker_choice_redirect.json` (A has ST01-005 in slot1; B has ST01-008 in slot1 and ST01-005
    in slot2), use `POST /api/game/player/playerAction` with `actionType: attackUnit` targeting B slot2.
  - Expect: The response indicates a blocker selection flow is required and provides an `eventId`.
  - Action: Call `POST /api/game/player/confirmBlockerChoice` selecting ST01-008 (`carduid`, `zone`, `playerId`), then
    inspect `gameEnv`.
  - Expect: ST01-008 becomes rested and the attack target is redirected to ST01-008 (current battle target matches the
    blocker carduid).

  2. Rested blocker does not create a blocker choice

  - Setup: Player A has a unit in slot1 to attack with. Player B has ST01-008 in slot1 but already rested, and another
    unit in slot2 as the target. currentPlayer = A, phase = MAIN_PHASE.
  - Action: Load `ST01-008/blocker_no_choice_when_rested.json` (A has ST01-005 in slot1; B has rested ST01-008 in slot1
    and ST01-005 in slot2), use `POST /api/game/player/playerAction` with `actionType: attackUnit` targeting B slot2,
    then inspect `gameEnv`.
  - Expect: No blocker selection flow is triggered, and the attack proceeds against the original target.

  3. Blocker choice lists multiple active blockers

  - Setup: Player A has a unit in slot1 to attack with. Player B has two active ST01-008 units (slot1 and slot2) and a
    target unit in slot3. currentPlayer = A, phase = MAIN_PHASE.
  - Action: Load `ST01-008/blocker_choice_multiple_active.json` (A has ST01-005 in slot1; B has active ST01-008 in slot1
    and slot2, plus ST01-005 in slot3), use `POST /api/game/player/playerAction` with `actionType: attackUnit`
    targeting B slot3.
  - Expect: The response indicates a blocker selection flow is required and provides an `eventId` with multiple blocker
    options.
  - Action: Call `POST /api/game/player/confirmBlockerChoice` selecting one ST01-008 (`carduid`, `zone`, `playerId`),
    then inspect `gameEnv`.
  - Expect: The selected ST01-008 becomes rested and the attack target is redirected to the selected blocker.

  4. Blocker choice excludes rested blocker

  - Setup: Player A has a unit in slot1 to attack with. Player B has two ST01-008 units with one active (slot1) and one
    rested (slot2), plus a target unit in slot3. currentPlayer = A, phase = MAIN_PHASE.
  - Action: Load `ST01-008/blocker_choice_multiple.json` (A has ST01-005 in slot1; B has active ST01-008 in slot1, rested
    ST01-008 in slot2, plus ST01-005 in slot3), use `POST /api/game/player/playerAction` with `actionType: attackUnit`
    targeting B slot3.
  - Expect: The response indicates a blocker selection flow is required and provides an `eventId` with multiple blocker
    options, excluding the rested blocker.
  - Action: Call `POST /api/game/player/confirmBlockerChoice` selecting one ST01-008 (`carduid`, `zone`, `playerId`),
    then inspect `gameEnv`.
  - Expect: The selected ST01-008 becomes rested and the attack target is redirected to the selected blocker.
